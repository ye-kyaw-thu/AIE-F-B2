# Myanmar NLP: Tokenizer ကွာခြားမှု အသေးစိတ် လေ့လာဆန်းစစ်ချက်
## XLM-RoBERTa (SentencePiece BPE) vs mBERT (WordPiece)

---

### ၁။ နိဒါန်း (Executive Summary)

Multilingual Pretrained Transformer Model များ (ဥပမာ - **XLM-RoBERTa** နှင့် **mBERT**) ကို မြန်မာဘာသာစကားကဲ့သို့ Non-Latin, Low-Resource Script များပေါ်တွင် Fine-tuning ပြုလုပ်ရာတွင် Model Architecture (Self-Attention Layer အရေအတွက်၊ Hidden Size) သာမက **Tokenizer ၏ အလုပ်လုပ်ပုံနှင့် Vocabulary ဖွဲ့စည်းပုံသည် ရလဒ်အပေါ် ကြီးမားသော သက်ရောက်မှု ရှိပါသည်။**

* **XLM-RoBERTa** သည် **SentencePiece (Byte-Pair Encoding - BPE)** algorithm ကို အသုံးပြုပြီး Vocabulary အရွယ်အစား **250,002** ရှိသည်။
* **mBERT (bert-base-multilingual-cased)** သည် **WordPiece** algorithm ကို အသုံးပြုပြီး Vocabulary အရွယ်အစား **119,547** သာ ရှိသည်။

ဤစာတမ်းတွင် Algorithm နှစ်ခု၏ ကွာခြားချက်၊ မြန်မာစာအပေါ် လက်တွေ့ Tokenizer ခွဲထုတ်မှု ရလဒ်များ (Empirical Tokens) နှင့် အဘယ်ကြောင့် XLM-RoBERTa ၏ Tokenizer က မြန်မာစာအတွက် ပိုမို သင့်လျော်ထိရောက်သည်ကို အသေးစိတ် ရှင်းလင်းထားပါသည်။

---

### ၂။ Tokenizer Algorithm နှစ်ခု၏ အခြေခံ သဘောတရားများ

| အချက်အလက် | XLM-RoBERTa (`xlm-roberta-base`) | mBERT (`bert-base-multilingual-cased`) |
| :--- | :--- | :--- |
| **Algorithm** | **SentencePiece (BPE)** | **WordPiece** |
| **Total Vocabulary** | **250,002 tokens** (~2.5 သိန်း) | **119,547 tokens** (~1.2 သိန်း) |
| **ဘာသာစကား အရေအတွက်** | 100 Languages | 104 Languages |
| **Pre-tokenization အားထားမှု** | Whitespace-independent (Space မလို) | Whitespace-dependent (Space အားကိုးရသည်) |
| **Space သတ်မှတ်ပုံ** | Space ကို Character တစ်ခုအဖြစ် မြင်သည် (`_` U+2581) | Space ကို delimiter အဖြစ် ဖြတ်ပစ်သည် |
| **Subword Prefix Notation** | မူလစကားလုံးအစတွင် `_` (Underscore) တပ်သည် | စကားလုံးနောက်ဆက်တွင် `##` တပ်သည် |
| **မြန်မာစာ Quota** | ပိုမိုကြီးမားသော Vocab pool မှ မြန်မာစာအတွက် နေရာပိုရသည် | 104 ဘာသာခွဲဝေရသဖြင့် မြန်မာစာ Quota အလွန်နည်းပါးသည် |

---

#### (က) WordPiece (mBERT) ၏ အလုပ်လုပ်ပုံနှင့် ကန့်သတ်ချက်များ
1. **Whitespace-dependent Pre-tokenization:**
   * WordPiece သည် မူလက English/German ကဲ့သို့ စကားလုံးကြားတွင် Space (Whitespace) ပုံမှန်ခြားထားသော ဘာသာစကားများအတွက် ဦးတည်ထားသည်။
   * ပထမအဆင့်တွင် စာသားကို Whitespace ဖြင့် အရင်ဖြတ် (Pre-tokenize) ပြီးမှသာ ရရှိလာသော စကားလုံးတစ်လုံးချင်းစီကို Vocab ထဲရှိ subword များနှင့် တိုက်ဆိုင်စစ်ဆေးသည်။
   * **မြန်မာစာ ပြဿနာ:** မြန်မာစာသည် ပုံမှန်အားဖြင့် စကားလုံးကြား Space မခြားဘဲ စာကြောင်းတစ်ခုလုံး ဆက်တိုက်ရေးသားသော ဘာသာစကား (Unsegmented Script) ဖြစ်သည်။ အကယ်၍ Preprocessing တွင် စကားလုံး မခွဲထားပါက WordPiece သည် စာကြောင်းတစ်ခုလုံးကို စကားလုံးကြီးတစ်ခုအဖြစ် မြင်ပြီး Vocab ထဲ ရှာမတွေ့တော့သဖြင့် အက္ခရာတစ်လုံးချင်းစီ (`Character-level`) အထိ ပြုတ်ထွက်သွားရသည်။

2. **Subword Prefix `##`:**
   * WordPiece သည် စကားလုံးတစ်ခု၏ အစမဟုတ်သော နောက်ဆက်များကို `##` ဖြင့် သတ်မှတ်သည် (ဥပမာ - `မ`, `##ြ`, `##န်`, `##မာ`)။
   * မြန်မာစာတွင် ဗျည်း၊ သရ၊ အသတ်၊ အောက်မြစ်များကို `##` ဖြင့် မလိုအပ်ဘဲ အလွန်အမင်း အပိုင်းပိုင်းခွဲပစ်လေ့ရှိသည်။

---

#### (ခ) SentencePiece BPE (XLM-RoBERTa) ၏ အားသာချက်များ
1. **Language-agnostic & Raw Text Input:**
   * SentencePiece သည် Whitespace ကို အထူးအဆန်းအဖြစ် မမြင်ပါ။ စာသားတစ်ခုလုံးကို Byte Sequence အဖြစ် တိုက်ရိုက် ကြည့်ရှုသည်။
   * Space ကိုလည်း သာမန်သင်္ကေတတစ်ခုဖြစ်သော `_` (U+2581 meta-symbol) အဖြစ် အစားထိုး သိမ်းဆည်းသည်။
   * ထို့ကြောင့် စာသားထဲတွင် Space ပါသည်ဖြစ်စေ၊ မပါသည်ဖြစ်စေ Data ထဲတွင် အကြိမ်ရေအများဆုံး တွေ့ရသော စာလုံးတွဲများ (Frequent N-grams / Subwords) ကို အလိုအလျောက် ပေါင်းစပ်ဖမ်းယူနိုင်သည်။

2. **Larger Vocabulary (250k vs 120k):**
   * Vocabulary ပမာဏ ၂ ဆကျော် ပိုများသည့်အတွက် Low-resource ဘာသာစကားဖြစ်သော မြန်မာစာအတွက် စကားလုံးအပြည့်အစုံ (Full Words) နှင့် အသုံးများသော စကားစုများ (Compound Words) ကို Vocabulary ထဲတွင် တိုက်ရိုက် သိမ်းဆည်းထားနိုင်စွမ်း ရှိသည်။

---

### ၃။ မြန်မာစာ လက်တွေ့ စမ်းသပ်ချက် ရလဒ်များ (Empirical Comparison)

တူညီသော မြန်မာစာနမူနာများကို XLM-RoBERTa နှင့် mBERT Tokenizer နှစ်ခုဖြင့် စမ်းသပ်ခွဲထုတ်ထားသော လက်တွေ့ Output များ ဖြစ်ပါသည် -

```
=== Vocab Sizes ===
XLM-RoBERTa Vocab Size : 250,002
mBERT Vocab Size       : 119,547
```

---

#### နမူနာ (၁) - "မြန်မာ့ တပ်မတော်"
* **XLM-RoBERTa (၄ tokens):**
  ```python
  [' မြန်မာ', '့', ' ', 'တပ်မတော်']
  ```
  > **သုံးသပ်ချက်:** `မြန်မာ` နှင့် `တပ်မတော်` ဟူသော အဓိပ္ပာယ်ပြည့်စုံသည့် စကားလုံးကြီး ၂ လုံးကို သီးခြား Single Token အဖြစ် တိုက်ရိုက် သိမ်းဆည်းထားနိုင်သည်။

* **mBERT (၉ tokens):**
  ```python
  ['မ', '##ြ', '##န်', '##မာ', '##့', 'တ', '##ပ်', '##မ', '##တော်']
  ```
  > **သုံးသပ်ချက်:** အဓိပ္ပာယ်ရှိသော စကားလုံးမဖြစ်ဘဲ ဗျည်း၊ ရရစ်၊ သရ၊ အသတ် (`မ` + `##ြ` + `##န်`...) အဆင့်အထိ ၉ ပိုင်းတိတိ စုတ်ပြတ်သွားသည်။

---

#### နမူနာ (၂) - "ရခိုင်ပြည်နယ်"
* **XLM-RoBERTa (၃ tokens):**
  ```python
  [' ရ', 'ခိုင်', 'ပြည်နယ်']
  ```
  > **သုံးသပ်ချက်:** `ပြည်နယ်` ဟူသော စကားလုံးကို Token တစ်ခုတည်းအဖြစ် သိမ်းဆည်းထားနိုင်သည်။ စုစုပေါင်း ၃ tokens သာ သုံးသည်။

* **mBERT (၇ tokens):**
  ```python
  ['ရ', '##ခ', '##ိုင်', '##ပ', '##ြ', '##ည်', '##နယ်']
  ```
  > **သုံးသပ်ချက်:** `ရ`, `##ခ`, `##ိုင်`, `##ပ`, `##ြ`, `##ည်`, `##နယ်` ဟူ၍ အက္ခရာ/သရ ၇ ပိုင်း ကွဲထွက်သွားသည်။

---

#### နမူနာ (၃) - "စစ်အာဏာရှင်"
* **XLM-RoBERTa (၃ tokens):**
  ```python
  [' စစ်', 'အာဏာ', 'ရှင်']
  ```
  > **သုံးသပ်ချက်:** အလွန်လှပစွာ Morpheme အဆင့် ခွဲထုတ်နိုင်သည် (`စစ်` + `အာဏာ` + `ရှင်`)။ အဓိပ္ပာယ်ယူနစ် (Semantic units) ၃ ခု အတိအကျ ရရှိသည်။

* **mBERT (၈ tokens):**
  ```python
  ['စ', '##စ်', '##အ', '##ာ', '##ဏ', '##ာ', '##ရ', '##ှင်']
  ```
  > **သုံးသပ်ချက်:** `စ`, `##စ်`, `##အ`, `##ာ`, `##ဏ`, `##ာ`, `##ရ`, `##ှင်` ဟူ၍ ၈ ခုအထိ ပြုတ်ထွက်သွားသည်။

---

#### နမူနာ (၄) - Assignment-7 Dataset ထဲမှ အမုန်းစကား/ဝင်ရိုးစွန်း စာကြောင်းရှည်
**စာသား:**
> *"ဒီခွေး တွေ ကို ဖမ်းမိ ရင် ဆေးကုပေးရတာ နဲ့ ကျွေးမွေးရတာ နဲ့ စစ်ခွေး ကို ခွေးနဲ ပါ နှိုင်း လို့ မတန်ဘူး"*

* **XLM-RoBERTa Token Count:** **41 tokens**
* **mBERT Token Count:** **59 tokens (+43.9% ပိုရှည်သွားသည်!)**

### ၄။ Model Performance အပေါ် သက်ရောက်သည့် အဓိက အချက် ၃ ချက်

```
                  ┌──────────────────────────────────────────────┐
                  │          မြန်မာစာ Tokenizer ကွာခြားမှု          │
                  └──────────────────────┬───────────────────────┘
                                         │
         ┌───────────────────────────────┴───────────────────────────────┐
         ▼                                                               ▼
┌─────────────────────────────────┐            ┌──────────────────────────────────┐
│  XLM-RoBERTa (SentencePiece)   │            │        mBERT (WordPiece)         │
├─────────────────────────────────┤            ├──────────────────────────────────┤
│ • 41 Tokens (Sequence ကျစ်လျစ်)   │            │ • 59 Tokens (Sequence အလွန်ရှည်)  │
│ • Morpheme/Word-level semantics │            │ • Character/Diacritic fragmentation│
│ • "တပ်မတော်" = 1 Token          │            │ • "တပ်မတော်" = 4 Tokens          │
│ • Attention အား စကားလုံးအဆင့်သုံးနိုင် │            │ • Attention အား စာလုံးပေါင်းရန်ဖြုန်းရ │
│ • Context Window အလဟဿမဖြစ်      │            │ • 128 Max Length တွင် စာသားပြတ်လွယ် │
└─────────────────────────────────┘            └──────────────────────────────────┘
```

#### (၁) Sequence Length & Context Window Truncation (အချက်အလက် ပြတ်ကျန်ခြင်း)
* Transformer Model များတွင် Memory နှင့် Compute ကန့်သတ်ချက်အရ `max_length` ကို ၁၂၈ သို့မဟုတ် ၂၅၆ အဖြစ် ကန့်သတ်လေ့ရှိသည်။
* mBERT သည် စာလုံးတစ်လုံးတည်းကိုပင် 2x မှ 3x အထိ အပိုင်းပိုင်း ခွဲပစ်သောကြောင့် Token ပမာဏ လျင်မြန်စွာ ပြည့်သွားပြီး စာကြောင်းရှည်များတွင် နောက်ပိုင်း စာသားများ **Truncation (ပြတ်ကျန်ခဲ့ခြင်း)** ဖြစ်လွယ်သည်။
* XLM-RoBERTa သည် Sequence ကို ကျစ်လျစ်စွာ ထိန်းသိမ်းနိုင်သောကြောင့် Context အပြည့်အစုံကို Model က မြင်တွေ့နိုင်သည်။

#### (၂) Semantic Representation vs Character-level Burden (အဓိပ္ပာယ် ဖော်ဆောင်နိုင်စွမ်း)
* **XLM-RoBERTa:** `တပ်မတော်` ဟူသော စကားလုံးသည် Embedding Space ထဲတွင် Vector တစ်ခုတည်းအဖြစ် တည်ရှိသည်။ ထို့ကြောင့် Model ၏ အပေါ်ယံ Attention Layer များသည် ၎င်း၏ နိုင်ငံရေး/ဝင်ရိုးစွန်း အဓိပ္ပာယ်ကို တိုက်ရိုက် ချိန်တွက်နိုင်သည်။
* **mBERT:** `တ`, `##ပ်`, `##မ`, `##တော်` ဟူသော အစိတ်အပိုင်း ၄ ခုကို Embedding Vector ၄ ခု အဖြစ် အရင်သိမ်းဆည်းရသည်။ Model သည် ပထမအဆင့် Self-Attention Layer များတွင် အဆိုပါ ၄ ခုကို ပြန်လည်ပေါင်းစပ်ပြီးမှသာ `တပ်မတော်` ဖြစ်ကြောင်း နားလည်ရသည်။ ဤသည်မှာ Model Parameters များကို အဓိပ္ပာယ်ဖော်ဆောင်ခြင်းထက် **စာလုံးပေါင်းစပ်ခြင်း (Orthographic assembly)** အတွက် ဖြုန်းတီးလိုက်ရသကဲ့သို့ ဖြစ်စေသည်။

#### (၃) Consonant & Diacritic Splitting (ဗျည်းနှင့် သရ/အသတ် ပြုတ်ထွက်ခြင်း)
* မြန်မာစာသည် Alphabet မဟုတ်ဘဲ **Abugida စနစ်** ဖြစ်သည်။ ဗျည်းပေါ်တွင် သရ၊ ရရစ်၊ အသတ်၊ အောက်မြစ်တို့သည် တစ်သားတည်း ပေါင်းစပ်တည်ရှိသည်။
* mBERT ၏ WordPiece သည် Combining Unicode Characters များကို ဗျည်းမှ ခွဲထုတ်ပစ်ခြင်းကြောင့် Grammatical Structure နှင့် Phonetic Representation များ ပျက်ယွင်းသွားစေသည်။

### ၅။ ကျွန်ုပ်တို့၏ Data Preprocessing (Step 1) နှင့် ဆက်စပ်မှု

ကျွန်ုပ်တို့၏ Step 1 တွင် `mmdt-tokenizer` ကို အသုံးပြု၍ စကားလုံးများကြား Space ခြားပေးခဲ့ခြင်း (Word Segmentation) သည် Tokenizer နှစ်ခုလုံးအတွက် မည်သို့ အထောက်အကူပြုသနည်း -

1. **mBERT အတွက် ကယ်တင်ရှင်ဖြစ်ခဲ့ခြင်း:**
   * အကယ်၍ စကားလုံးများကြား Space မခြားထားပါက mBERT သည် စာကြောင်းတစ်ခုလုံးကို စကားလုံး ၁ လုံးတည်းအဖြစ် မှတ်ယူပြီး ပိုမိုဆိုးရွားစွာ အက္ခရာတစ်လုံးချင်းစီ ခွဲပစ်မည် ဖြစ်သည်။ Space ခြားပေးထားခြင်းကြောင့် အနည်းဆုံး စကားလုံးအစပိုင်းများကို ခွဲခြားနိုင်ခဲ့သည်။
2. **XLM-RoBERTa အတွက် သန့်ရှင်းသော Context ပေးနိုင်ခြင်း:**
   * XLM-RoBERTa သည် Space ကို `_` သင်္ကေတအဖြစ် မှတ်ယူသဖြင့် စကားလုံးအစပ်များတွင် ပိုမိုတိကျသော Subword N-grams များကို ဖွဲ့စည်းနိုင်စေခဲ့သည်။
